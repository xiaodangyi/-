# 验收视频操作指南

本文指令适用于当前 Windows 电脑，工作目录为 `E:\新建文件夹 (8)`。按顺序在同一个 PowerShell 窗口运行；新开窗口后先重新执行初始化部分。现有依赖、训练数据和正式模型已经准备好，录屏前无需再次安装或下载数据集。

## 一、当前效果与演示边界

当前默认模型登记在 `configs/selected-model.json`，对应 `outputs/improvement-20261020/augmentation-smoothing-enriched/best.pt`。使用手写 ResNet-18 从随机参数开始训练 30 轮，采用增强、标签平滑 0.1 和 78 张补图，最佳权重来自第 24 轮。按原验证集准确率优先、宏平均 F1 打破平分的规则选定，选型早于独立网络检验。

| 指标 | 原基线 | 当前默认模型 |
| --- | --- | --- |
| 最佳验证集准确率 | 81.34%，449/552 | 85.33%，471/552 |
| 原测试集准确率 | 84.48%，468/554 | 87.36%，484/554 |
| 原测试集宏平均 F1 | 0.8417 | 0.8726 |
| 独立网络检验准确率 | **85%，85/100** | **81%，81/100** |
| 网络检验宏平均 F1 | 0.8465 | 0.7952 |

原数据集内的表现有所提升，但独立网络图片出现回退，因此不能在 PPT 中声称本轮提高了所有场景的泛化能力。两套模型均保留，且没有按网络检验结果重新选型。六组实验仅使用种子 42；100 张网络图片每类 20 张，样本规模有限，结果不代表所有网上图片。完整实验和来源见 `docs/改进实验记录.md` 与 `data_provenance/`。

| 类别 | 中文 | 测试集中该类识别正确的比例（召回率） |
| --- | --- | --- |
| daisy | 雏菊 | 85/96，88.54% |
| dandelion | 蒲公英 | 125/135，92.59% |
| roses | 玫瑰 | 80/97，82.47% |
| sunflowers | 向日葵 | 101/106，95.28% |

郁金香是当前较弱的类别，网络检验仅正确 8/20，其中 10 张误判为玫瑰。应展示成功与失败案例。当前模型只支持以上五类；其他花、动物或日常物品也会被强制分到其中一类，尚不具备可靠的“未知类别”检测能力。输出概率是在这五类之间的相对分配，不是经过校准的正确率保证。

## 二、初始化终端

```powershell
Set-Location -LiteralPath 'E:\新建文件夹 (8)'
$python = 'C:\Users\LENOVO\Documents\Codex\2026-10-18\gen\anaconda-envs\ai-cuda\python.exe'
$selected = Get-Content -LiteralPath '.\configs\selected-model.json' -Raw -Encoding UTF8 | ConvertFrom-Json
$checkpoint = Join-Path (Get-Location).Path $selected.checkpoint
$modelRoot = Split-Path -Parent $checkpoint
$env:PYTHONIOENCODING = 'utf-8'
[Console]::OutputEncoding = [System.Text.Encoding]::UTF8
$demoStamp = Get-Date -Format 'yyyyMMdd-HHmmss'
$demoRoot = Join-Path (Get-Location).Path ('outputs\acceptance-' + $demoStamp)
New-Item -ItemType Directory -Path $demoRoot -Force | Out-Null
```

`$python` 指定已有 Anaconda 解释器；后续 `-s` 避免用户级 CPU 版包覆盖 CUDA 版。`$checkpoint` 读取本轮按验证集选定的权重；本次录像的新输出单独保存在 `$demoRoot`，不会覆盖既有结果。

## 四、现场展示训练

验收视频可以展示 2 轮实际训练，再展示正式 30 轮实验的曲线与结果。务必说明这 2 轮用于演示训练过程，最终识别仍使用已完成 30 轮的正式模型。

```powershell
$trainingDemo = Join-Path $demoRoot 'training-demo'
& $python -s -u .\scripts\train.py --manifest-dir $selected.manifest_dir --data-dir $selected.data_dir --output-dir $trainingDemo --epochs 2 --batch-size 32 --image-size 224 --device cuda --seed 42 --log-every 10 --augmentation crop-color --label-smoothing 0.1 --weight-decay 0.0001
```

每轮有 83 个训练批次和 18 个验证批次。讲解“随机裁切与颜色扰动 → 前向预测 → 计算带标签平滑的交叉熵损失 → 反向传播 → AdamW 更新参数”，再解释验证阶段不增强图片、不更新参数，验证损失使用普通交叉熵。如果希望每批都显示，将 `--log-every 10` 改为 `--log-every 1`。

`Ctrl+C` 可中断当前训练。已有最佳模型和完整轮次日志会保留，但当前版本不支持断点续训。重新演示请生成新的 `$demoRoot` 或使用新的输出目录。

如果想按本轮设置重新训练完整 30 轮，在可见 PowerShell 窗口执行下列命令，并使用新的输出目录：

## 六、用网络图片现场识别

先打开专门存放外部演示图片的目录：

```powershell
New-Item -ItemType Directory -Path '.\data\demo_images' -Force | Out-Null
Invoke-Item -LiteralPath '.\data\demo_images'
```

在浏览器中打开原始图片，使用“图片另存为”保存到 `E:\新建文件夹 (8)\data\demo_images`。先选择五类之内、主体清晰的一朵花，例如命名为 `rose01.jpg`、`sunflower01.png`。记录图片来源链接；演示时如使用与原数据集相同的图片，应如实说明，不能宣称是全新样本。

图片应是真实的 JPG、PNG、BMP 或 WebP 文件。下载到的是网页、HEIC 或 AVIF 时，应先用支持它的图片软件另存为 PNG/JPG；直接改扩展名不能完成格式转换。保存对话框中确认目标为 E 盘，避免默认保存到 C 盘下载文件夹。

先展示图片，再运行识别：

```powershell
$image = 'E:\新建文件夹 (8)\data\demo_images\rose01.jpg'
Invoke-Item -LiteralPath $image
& $python -s .\scripts\predict.py --image $image --device cuda
```

请把 `rose01.jpg` 换成真实文件名。不指定 `--checkpoint` 时自动读取本轮选定权重。程序按概率从高到低输出五类；第一行是本次预测类别，例如 `roses: 0.8700` 表示五类中玫瑰的输出概率约为 87%，不是保证一定正确。将 `$image` 改为另一张图片路径，再次运行最后一条命令即可。

同图查看原基线的结果：

```powershell
& $python -s .\scripts\predict.py --checkpoint .\outputs\experiment-002\best.pt --image $image --device cuda
```

如希望逐个识别目录中的全部图片：

```powershell
Get-ChildItem -LiteralPath '.\data\demo_images' -File |
    Where-Object { $_.Extension.ToLowerInvariant() -in @('.jpg', '.jpeg', '.png', '.bmp', '.webp') } |
    ForEach-Object {
        Write-Host ('正在识别：' + $_.Name) -ForegroundColor Cyan
        & $python -s .\scripts\predict.py --checkpoint $checkpoint --image $_.FullName --device cuda
    }
```

该循环每张图片重新加载一次模型，适合少量录像样例。预测不会更新模型，也不会自动学习新图片；如需学会新类别，需要带标签的数据、调整类别数并重新训练。

当前项目是命令行程序，运行预测脚本时会加载模型并在终端输出结果，不需要启动网页服务。图片预览由 Windows 默认图片程序负责。图片下载到本地后，推理可以离线进行。

## 七、本轮已完成的改进与下一步

以下三步已经完成，可作为 PPT 的实验过程：

1. **单因素实验。** 分别比较缩放裁切与颜色扰动、标签平滑 0.1、权重衰减 0.001，与原基线保持相同划分和 30 轮。增强的验证收益最明显。
2. **递进组合与补图。** 先组合增强＋标签平滑，再比较增大权重衰减；后者降低组合验证成绩，未采用。从 Wikimedia Commons 下载 347 张候选，经去重、逐图复核后选 78 张加入训练；100 张按作者隔离留作最终检验。
3. **锁定后再检验。** 按原验证集选定模型，保留 Git 记录后才运行网络检验。原测试集从 84.48% 到 87.36%，网络检验从 85% 到 81%；据实报告回退。补图仅使验证 F1 略高，准确率持平，不能声称明显有效。

下一轮建议另建覆盖五类、来源更分散的外部验证集，检查郁金香与玫瑰边界、裁切强度和样本比例，并比较多个随机种子。另留全新的最终测试图，本次已看过的 100 张只作历史检查。输入方向、主体裁切或未知类提示也需独立验证，不能只加一个概率阈值就保证可靠。

训练轮数更多或网络更大并不保证更好。预训练迁移学习可作为后续额外对照；按本次考核要求，手写残差块和 ResNet 仍需保留为主要实现。

## 八、建议的录像顺序

环境和开发历史 → 原数据与补图审核 → 手写残差结构 → 短训练演示 → 六组对照和 30 轮曲线 → 原测试集与网络检验结果 → 外部图片逐张识别 → 解释郁金香回退和下一步。

保留真实预测结果，预测错误时解释其含义。单张演示不能替代 554 张原测试集及 100 张网络检验的统计指标。个人感悟需结合本人实际操作补充，尚未实现的改进写入后续计划。
